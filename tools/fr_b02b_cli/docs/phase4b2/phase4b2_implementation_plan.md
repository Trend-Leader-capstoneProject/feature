## 범위와 완료 기준

첫 작업은 인증·검토 결정 경계의 계획과 첫 실패 테스트 명세 확정까지다. 이 시점에는 실행 코드, 실제 SID/허용 목록, 운영 ACL, C/E 저장소를 생성하지 않는다.

후속 구현은 SID 권한 확인 → 명시적 판단 → 보호 등록·백업 → 조회·철회 순서로 진행한다. 각 작은 단위에서 Red → Green → 관련 회귀를 수행한다. 최종 완료에는 B42-01~10과 실제 Windows의 합성 자료를 사용한 ACL·별도 디스크 복원·재시작 검증이 필요하다. 자동 테스트만으로 운영 검증을 대체하지 않는다.

보존할 계약은 4A의 정확한 `YES`, 원본 `HOLD/NONE`·관측자 미인증 수준·시각 원문, 4B-1의 출력과 읽기 전용 동작이다. 모든 4B-2 결과의 게시 권한은 `NONE`이다. Writer, DB DML, HTTP/RSS, 관리자 UI, G5/G6 승인은 제외한다.

## 인증·결정 경계의 작은 구현 순서

1. **인증 실패 차단:** 첫 테스트 명세를 코드로 옮긴다. 필요한 최소 내부 인터페이스와 실행 가능한 테스트 배선을 만든 뒤, SID 획득 실패가 판단/저장 경계까지 통과하는 행동 실패를 확인한다. Import/fixture/mock 오류는 Red로 계산하지 않는다. 차단 최소 구현 후 같은 테스트를 Green으로 만든다.
2. **권한 매칭:** 합성 활성 허용 SID의 정상 경로를 추가한 다음 미등록·비활성·역할 불일치·목록 손상·중복 키·접근 보호 불명확 반례를 차례로 추가한다. 정상 성공도 OS 토큰/ACL 실검증과 mock 검증을 구분한다.
3. **명시적 판단:** ACCEPTED/HOLD/REJECTED만 판단 사건으로 처리한다. 빈 입력/EOF/Ctrl+C는 취소(2), 수락 기본값과 추가 YES는 없다. HOLD/REJECTED는 비공백 사유, 사유 최대 500자. 유효하지 않은 결정/사유로 저장하지 않는다.
4. **시간·동일 바이트:** 판단 직후 UTC 측정, 4A 생성 시각보다 이르거나 시계가 역행하면 차단한다. 원문 시각을 보존하고 재확인 사이 입력 교체를 차단한다.
5. **실제 저장 연결:** 허용 목록/루트의 보호 상태를 검사하고 확정 전후 권한을 재검증한다. C/E의 필수 바이트·연결·ACL·완료 표식·복원 가능성 검증 전에는 성공하지 않는다. 그 후 중복/경합/철회/조회 실패 경로를 구현한다.

OS 인증·정책·시계·저장 경계는 자동 테스트에서만 주입한다. 공개 CLI에 `--reviewer`, `--sid`, 임의 보호 루트/허용 목록 옵션이나 인증 우회 환경변수를 추가하지 않는다. 실제 설정 물리 위치·형식·관리 책임과 운영 ACL은 미확정이므로 구현 전 환경 확인을 거쳐 기록하며, 검증되지 않은 기본 경로를 사용하지 않는다.

## 첫 실패 테스트 확정: B42-02 / SID 미확인

- **행동 이름:** `test_unavailable_process_sid_blocks_before_decision_or_store` (신규 Review Service의 단위/상호작용 테스트).
- **Given:** 적격 합성 A1/4A의 검증된 스냅샷, 보호 검증을 통과한 합성 허용 목록, 현재 프로세스 SID 조회가 실패하는 OS 경계 대역. 실제 SID·개인 경로·A1 자료는 사용하지 않는다.
- **When:** 검토 등록 유스케이스를 실행한다.
- **Then:** 인증 실패 범주의 BLOCKED, 성공 결과/유효 등록 ID 없음. 검토 결정 입력 및 보호 저장 호출 0회. 입력 ZIP/관측/인덱스 바이트와 HOLD/NONE 불변. 실제 SID·경로·원시 예외 내용이 공개 오류로 전달되지 않음.
- **Red 인정 조건:** 테스트 수집과 합성 입력 검증은 성공하고, 위 기대 행동의 assertion이 실패해야 한다. 아직 실행 코드를 작성하지 않았으므로 현재는 **명세 확정 / Red 미실행**이다.
- **이 테스트가 막는 회귀:** 신원을 확인하지 못한 실행을 익명/사용자명/수동 신원으로 대신 수락하거나, 인증 실패 뒤에도 판단·저장을 계속하는 경로.
- **바로 다음 CLI 계약 테스트:** 같은 인증 실패를 `review-register --zip ... --record-dir ...`에 연결하여 종료 1, `BLOCKED: <category>` 한 줄, 성공 JSON 없음과 비밀 미노출을 확인한다. 명령 미등록에 따른 argparse 종료 2만으로 SID 경계 Red를 입증했다고 하지 않는다.

## 허용 목록 구현 단위 — 2026-11-10 추가 결정과 검증

이 절은 위 초기 계획 이후의 사용자 결정과 구현 기록이다. FROZEN v1.0을 변경하지 않는다.

- **사용자 결정:** 이번 B42-02 단위에서는 운영 허용 목록의 물리 경로와 관리 책임을 미확정으로 유지한다. 실제 CLI는 보호된 설정이 없거나 검증 불가하면 BLOCKED/1이다. 합성 테스트에서만 내부 의존성으로 경로·보호 검증 결과를 제공한다. 공개 경로/SID/ACL 우회 옵션은 신설하지 않는다.
- **운영 후속 조건:** 운영 설정 경로, 초기 등록 담당자, 허용 목록 변경·폐기 책임, 실제 ACL 및 보호 읽기는 Protected Store 통합 시 확정하고 Windows 실환경 시험으로 검증한다. 이번 자동 테스트는 운영용 접근통제 완료 증거가 아니다.
- **내부 입력 형식:** UTF-8 JSON, 최대 65,536바이트. 최상위 정확한 키는 `schema=FR_B02B_REVIEWER_ALLOWLIST_V1`, `reviewers`(배열). 항목의 정확한 키는 `sid`(Windows SID 문자열), `active`(boolean), `role=EVIDENCE_REVIEWER`이다. 중복 키/SID, 추가·누락 필드, 잘못된 타입·역할·SID 및 비유한 수는 차단한다. 같은 SID의 활성 역할만 다음 검토 단계 준비에 사용하며, 등록 성공/게시 권한은 부여하지 않는다.
- **책임:** 신규 `fr_b02b_reviewer_allowlist.py`가 보호된 파일 바이트의 파싱과 대조를 소유한다. Service는 입력 검증 → OS SID → 허용 목록 검증 순서로 준비하고, 실제 등록은 계속 차단한다. 기본 운영 source provider는 미설정 오류를 내며, 테스트 보호 대역을 실제 Native ACL 검증기로 간주하지 않는다.
- **Native 검토:** 기존 SID 조회의 `ctypes` 타입·반환값 검사와 중첩 finally 해제 구조를 공식 계약과 대조했다. 성공 및 OpenProcessToken/크기 조회/TokenUser 조회/변환/LocalFree/CloseHandle 장애를 합성 대역으로 검증했다. 발견된 결함이 없어 SID 조회 코드는 변경하지 않았다.
- **Red:** 허용 목록 미구현/미연결 상태에서 7개 테스트를 실행하여 14개 실패·2개 오류를 확인했다. CLI의 미등록/비활성 SID가 준비 경계를 통과하고, 목록 누락·손상·보호 실패를 판별하지 못하는 행동 실패였다. Import/fixture 오류는 아니었다.
- **Green 및 회귀:** Python 3.14에서 허용 목록 9개, Native 경계 2개를 포함한 전체 **118개 / OK**. 기존 107개 테스트 파일은 수정하지 않았다. 허용 SID·미등록/비활성·누락/손상·보호 검증 실패, 프롬프트/Store/ID 생성 0건, 원본 HOLD/NONE·바이트 보존, 공개 우회 옵션 부재를 검증했다.
- **추가 설정 실패 반례:** 설정 공급자의 PermissionError가 원시 오류로 전파되는 Red 1건을 확인하고, 공급자 경계에서도 범주 오류로 변환한 뒤 동일 테스트 및 전체 118개 Green을 확인했다. 운영 설정이 불명확한 경우를 허용 SID로 대체하지 않는다.
- **구현 중 수정:** Windows의 path stat/fstat 간 st_ctime_ns 차이로 발생한 정상 파일 오탐을 재현했다. 파일 식별자·크기·수정 시각 및 보호 상태 전후 대조는 유지하고, 일관되지 않은 ctime의 비교를 제거했다. 결정적인 회귀 테스트를 추가했다. 모든 적대적 파일 교체/ACL 경합을 해결했다는 주장은 하지 않는다.
- **도구:** Ruff 미설치. 정적 검사 완료나 Python 3.12 PASS를 주장하지 않는다. 실제 운영 ACL 생성/변경, 원격 쓰기, 커밋·푸시·PR은 수행하지 않았다.
