# Trend Leader 실데이터 연결 — 사전 설계 결정 기록 v0.1

> 상태: **DESIGN REVIEW / NOT FROZEN**
> 기준: GitHub `dev` HEAD `0ce3f41cba8e64a40d8175506e44a20508f55f6e` (2026-10-27 확인)
> 목적: 외부 소스 선정과 실데이터 연결 설계 전, 결정·관찰·미확정 사항의 최소 기록
> 비범위: API/Schema 변경 확정, 자동 수집 구현, 기존 Frozen 계약 수정, 외부 서비스 이용 허가의 확대 해석

## 1. 문제 정의

기존 전체·개인화 트렌드 목록 조회는 구현되어 있으나 실제 외부 트렌드 수집 파이프라인은 별도로 설계·구현해야 한다. 현재 데모 데이터 중심의 화면을, 적법하게 획득한 실제 트렌드 주제와 원문 출처로 연결하는 최소 경로를 먼저 검증한다.

## 2. 현재 채택한 방향(사용자 결정)

1. **제품 목표:** 운영자 개입 없이 트렌드가 주기적으로 발굴·검증·공급되는 구조를 유지한다. 수동 데이터 등록 앱으로 목표를 변경하지 않는다.
2. **MVP 우선 방식(A):** 외부에서 이미 식별된 트렌드 주제 또는 급상승 키워드를 이용한다. 영상·기사·게시물에서 주제를 새로 추출하는 콘텐츠 중심 방식(B)은 후속으로 미룬다.
3. **초기 검증 전략:** 필요한 경우 운영자가 제한적으로 후보 품질을 검토한다. 이는 임시 검증 단계이며 최종 운영 방식이 아니다.
4. **후보 채택 근거:** 신뢰할 수 있는 관련 원문 출처를 실제 후보 채택의 필수 증거로 둔다(기존 목록 API의 `latest_source=null` 방어 계약은 유지). NAVER 검색 관심도는 내부 보조 검증이며 세부 자동 채택 규칙은 아직 확정하지 않는다.
5. **AI 역할:** 목록의 기본 `summary`와 후속 AI 상세 분석은 별도 책임이다. 실데이터 목록 연결에 AI 상세 분석 생성을 필수로 묶지 않는다.

## 3. 외부 소스 검토 현황

| 소스 | 관찰된 적합성 | 이용·연동 상태 | 현재 판정 |
| --- | --- | --- | --- |
| Google Trends Trending now | 실제 급상승 검색어 관찰, 분야 편중·모호한 주제 존재 | 자동 수집·가공·저장·배포 권한 미확정 | **주제 중심 후보, 조건부** |
| YouTube Gaming | 인기 게임/실시간 콘텐츠 관찰 가능, 개별 트렌드 사건은 미확정 | 게임 탐색 UI와 `videos.list`는 동일한 목록 보장 없음; 파생 데이터·보관 정책 추가 검토 | **보조 관찰, B형 자동 추출은 후속** |
| GDELT | 뉴스·사건 관련 출처 탐색에 유용할 수 있으나 생활·콘텐츠 분야 한계 관찰 | 공개 데이터와 원문 기사 권리 분리 필요 | **뉴스 보조 후보** |
| Mastodon | 별도 관찰 미완료 | 인스턴스별 대표성 및 이용 조건 추가 확인 | **검토 보류** |
| NAVER API HUB 검색어 트렌드 | 지정 키워드의 상대 검색 관심도 보조 검증; API 호출 PoC 보고됨 | 고객지원 회신 기준 내부 판단용 보관·분석 가능, 외부 AI 제공·원본/파생 지표 외부 공개 불가 | **내부 검증용 조건부** |

> 수동 화면 관찰 결과는 API 자동 연동 성공이나 해당 데이터를 DB에 저장·재배포할 허가를 의미하지 않는다.

## 4. NAVER 고객지원 회신 적용 경계

- 적용 약관: 2026-10-07 시행 NAVER API HUB 일반조건. '네이버 검색 API 서비스' 특약은 검색어 트렌드에 적용되지 않는다는 고객지원 회신.
- `period`, `ratio` 원본 및 증가율·추세 가공 결과의 **내부 판단용 저장·분석은 조건부 가능**. 해당 자료 및 파생 지표의 앱 공개는 금지.
- 원본값과 가공값 모두 OpenAI 등 **외부 AI 서비스에 전달하지 않는다**.
- 운영자가 직접 판단·작성한 콘텐츠 제공은 조건부로 가능하다는 회신을 받았으나, **운영자 없는 시스템 자동 채택·공개는 추가 문의 답변 대기**.
- NAVER 데이터는 절대 검색량·플랫폼 공통 인기순위가 아니다. 내부 검증 지표를 목록의 `ranking`/`score` 또는 공개 `summary`와 동일시하지 않는다.

## 5. 기존 Frozen 계약(변경 금지)

- 공개 전체 목록 `GET /api/trends` 및 인증된 개인화 목록 `GET /api/trends/personalized`의 요청·응답·Cursor·권한 계약 유지.
- `ACTIVE` Trend 최신순 `(last_collected_at DESC, trend_id DESC)`, 기존 `latest_source`/`categories` 응답과 nullable `summary`/`thumbnail_url` 계약 유지.
- 사용자의 관심 대분류와 트렌드의 활성 세부분류 매핑 정책 유지. 신규 데이터가 기존 분류에 적합하지 않다는 이유로 임의 Category 추가·활성화를 수행하지 않는다.
- 실제 Writer 설계 시 `normalized_title` 충돌, `(trend_id, source_key)` 중복, 최신 Source 선택 `(collected_at DESC, source_id DESC)`, UTC 기준 수집 시각 및 반복 관측으로 인한 목록 이동 위험을 별도 검증한다.
- 기존 Demo Seed와 외부 수집 Writer를 동일한 완료 상태로 취급하지 않는다.

## 6. 다음 Design First Pass에서 확인할 항목

1. **이용 권한:** 주제/원문 URL의 자동 수집·가공·내부 저장·앱 공개가 허용된 실사용 소스가 있는가?
2. **최소 필드:** 제목, 관련 원문 URL, 확인 가능한 수집 시각, 활성 세부분류 매핑을 어떻게 확보할 것인가? `summary`/`thumbnail_url`은 nullable이다.
3. **자동성:** 수동 등록 실험과 반복 자동 수집을 구분하며, 재실행·중복·부분 실패 시의 성공 조건은 무엇인가?
4. **NCP 회신:** 내부 NAVER 지표를 이용한 **무인 자동 채택·앱 공개**가 허용되는가? 답변 수신 전 관련 사용 방식은 확정하지 않는다.
5. **Acceptance:** 허용된 실제 데이터 1~3건이 기존 목록에 노출되는 연결 검증과 주기적 무인 공급 완료를 별도 판정한다.
