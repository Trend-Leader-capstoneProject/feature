# Trend Leader — FR-B02b 관측 증거 경량화 보완안 v0.2 (DRAFT)

> 기준: 2026-11-09 (KST) / 사용자 방향: **수동 작업 최소화, 인프라 집중**  
> 상태: **DESIGN REVIEW / 미동결 / 미구현 / 실제 관측 증거 미생성 / G5·G6 HOLD**  
> 기반: FR-B02b v0.1 REVIEW DRAFT, P4 Final Review Addendum v0.2 §5.3~5.6, Python 3.15 G4 v0.7 N절, 운영 Gate v0.3  
> 제한: 기존 P4-DEC-01~20, A1 v0.2 콘텐츠 스냅샷·`content_ref`, RSS P0~P3 FROZEN, 기존 DB/API 계약 불변. 실제 Google RSS 호출·데이터 게시·운영 DB 쓰기 금지.

## 1. 결정 방향과 문제

기존 v0.1의 수동 메모/시각/해시/증거 ID/연결 입력은 인적 오류와 MVP 작업량을 증가시킨다. **관측 행위를 사람에게 남기되, 메타데이터 생성과 증거 보존은 작은 별도 도구가 담당하도록 설계한다.** 단, 도구가 URL 접속에 성공했다고 원문 사실 검증이나 제3자 이용 권리를 검증한 것은 아니다.

| 안 | 사용자 개입 | 얻는 증거 | 결론 |
|---|---|---|---|
| A. 수동 기록 | URL·시각·본문 사실·ID·해시·검토 결과 직접 입력 | 실제 수동 확인을 표현 가능하지만 기록 신뢰성 및 운영 부담 큼 | 비권고 |
| B. 사람이 링크 확인 → 도구에서 명시적으로 확인 1회 | 실제 원문 육안 확인과 내용 일치 체크 1회 | 도구가 **확인 동작 시점**을 시각·URL·승인 참조·증거 파일과 연결 | **MVP 권고 / 설계 검토** |
| C. HTTP 200 응답만 자동 수집 | 0회 | URL 접근성·응답 메타데이터만 확인 | 링크 QA에 사용 가능. 승인 콘텐츠의 사실·수동 수집 증거 대체 불가 |

## 2. 최소 작업 흐름 (제안, 아직 미구현)

1. 도구는 서버가 관리하는 **기존 보호된** A1 v0.2 승인 스냅샷에서 `trend_ref`, `content_ref`, `review_evidence_id`, `source_url`을 읽는다. 사용자가 이를 재입력하지 않는다. 기록 전 A1 동일성·G4 연결 상태를 재검증한다.
2. 도구가 승인된 원문 URL을 **사용자의 브라우저**로 열도록 지원한다. 기사 본문·이미지·OG 콘텐츠를 자동 수집/보관하지 않는다. 브라우저를 열었다는 사실만으로 검증 완료라고 표기하지 않는다.
3. 사용자는 링크의 대상과 승인된 핵심 사실을 직접 확인한 뒤 **원문 확인 완료 / 불일치·확인 불가** 중 한 번 선택한다. 불일치 또는 미확인은 HOLD. 확인하는 순간을 새로운 관측 사건으로 기록하며, 2026-11-04 시각으로 소급하지 않는다.
4. 도구는 통제된 시스템 시계에서 실제 확인 동작 시각(`observed_at`)과 기록 시각(`recorded_at`)을 timezone-aware 값으로 생성하고, `evidence_id`, 서식 버전, 출처 URL, 결과, 기록 주체 참조를 자동 구성한다. 시계 동기화·타임존/UTC 검증 실패 시 HOLD.
5. 보호된 증거 원본과 별도 참조 인덱스/다이제스트를 **원자적으로 보관**한다. 증거 저장 실패/부분 쓰기/검증 불가 시 성공 응답 금지. 실제 보관 위치·권한·백업은 FR-B03/05 인프라 검증과 연계하되, 파일 저장을 영속 Journal과 동일시하지 않는다.
6. P4 Envelope의 기존 `observation_evidence_ref`는 보호 인덱스의 불변 논리 ID만 가리킨다. Writer는 원본·인덱스·A1 해시·G4 유효성·승인 변경·G6를 **독립 검증**한다. 최종 게시 여부는 G5/G6 Gate에 따르며 현재 HOLD.

**중요한 구분:** 기존 링크의 단순 최신 상태 재확인(`SOURCE_LINK_RECHECK`)과 **새 콘텐츠 출처 취득 이벤트**(`MANUAL_SOURCE_COLLECTION`)는 다르다. 이 도구에서 `MANUAL_SOURCE_COLLECTION`을 허용하려면 사용자가 **그 시점에 출처를 실제로 확인하고 MVP 콘텐츠의 근거로 새로 취득했다는 뜻**을 확인해야 한다. 단순 과거 방문 기록 재표시나 자동 URL 접근은 `collected_at` 근거로 승격할 수 없다.

## 3. 자동 생성과 사람 확인의 책임 경계

| 데이터 또는 검증 | 처리 주체 | 정책 |
|---|---|---|
| 승인된 제목·요약·URL·A1 `content_ref` | 기존 보호된 A1 승인 자료에서 로드 | 수동 재입력·자동 편집 금지 |
| 원문 대상·핵심 사실 일치 | 담당자 1회 확인 | 도구는 자동으로 `CONFIRMED`를 선언할 수 없음 |
| 이벤트 ID·관측 확인 시각·기록 시각·메타데이터 | 경량 도구 | 실제 발생 시각만 사용, UTC/offset 검증 |
| 최소 원본 기록·다이제스트·참조 색인 | 경량 도구+보호 저장소 | 원본 복제 최소, 무결성·접근통제 검증 실패 시 HOLD |
| 관측 증거 검토·승인 효과 | 지정된 책임자의 확인·정책 | 사람의 관측 확인을 **G4/G6 승인 또는 제3자 권리 확인으로 자동 승격하지 않음** |
| DB 최초·최종 수집 시각 | 나중에 검증된 P4 Writer | `MANUAL_SOURCE_COLLECTION`이 실제로 입증된 경우에만 시간 매핑 검토 |

### 승인자와 검토자의 수동 작업 최소화

- MVP-A의 G4 일반 콘텐츠는 이미 기능 담당자가 개별 승인하는 구조다. 관측 담당자와 확인 담당자를 반드시 **서로 다른 사람**으로 지정하는 요구가 기존 정책에서 확정된 것은 아니다.
- 동일 역할의 **1회 확인 동작으로 관측과 검토를 함께 기록할 수 있는지**는 승인 주체 식별/검토 기준의 **추가 확정 사항**이다. 자동으로 `review_result=ACCEPTED`를 입력하는 구현을 미리 가정하지 않는다.
- 역할 검증이 불가능하거나 확인 동작의 책임 추적이 안 된다면 `review_result=HOLD`로 남긴다. **수동 한 번으로 모든 Gate를 완료한다는 약속이 아니다.**

## 6. 수용 기준 (우선 필요한 최소 검증)

- `L-01`: 이미 승인된 URL·해시·증거 ID가 자동 로드되며 수동 내용 재입력 없음.
- `L-02`: 확인 동작 전 `CONFIRMED` 증거가 생성되지 않음; 확인 불가·원문 변동·URL 불일치는 HOLD.
- `L-03`: 새 관측 시간은 실제 확인 시각과 offset을 사용; 과거 G4 승인일이나 외부 발표일로 대체하지 않음.
- `L-04`: 원본 파일·참조·다이제스트 중 하나라도 누락/변조되면 HOLD. 부분 기록 또는 저장소 쓰기 실패를 성공으로 처리하지 않음.
- `L-05`: 다른 `trend_ref`/`content_ref`/`source_url`로 관측 증거를 재사용하면 HOLD.
- `L-06`: 사용자 클릭 없이 G4/G6 승인·권리/사실 확인 상태를 승격하지 않음; 인프라 통제 미검증 시 운영 게이트 HOLD.
- `L-07`: 검증된 신규 수동 수집 이벤트만 `collected_at` 후보로 매핑; 단순 재확인은 금지.

## 7. 사용자에게 남기는 작업과 현재 판정

**최소 수동 작업 목표:** 이미 승인된 Python 3.15 출처를 도구가 열면 원문을 직접 보고 **'일치 / 불일치' 한 번 확인**. 메타데이터/시각/ID/지문 생성, 저장, 참조 연결은 자동 처리. 실제 역할/검토 절차가 확정되지 않으면 추가 확인이 필요할 수 있음.

**이번 보완안의 완료:** 간소화 목표와 논리적 책임 경계 확정 전 검토안 작성. **미완료:** 구현, 실제 보호 볼륨·권한·시계 환경 검증, 실제 관측, G5/G6 승인. 기존 P4 v0.2·FR-B02b v0.1은 변경하지 않는다. 동결·운영 전 실제 책임 경계(같은 담당자의 한 번 확인 가능 여부), 저장소 위치/권한만 우선 검증한다.
