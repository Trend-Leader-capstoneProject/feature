## 기능 범위

- 홈 왼쪽 사이드바: 공개 프로필·내 정보·로그아웃, 톱니바퀴의 앱 설정 진입.
- 별도 내 정보 화면과 개별 중앙 팝업을 통한 사진/닉네임 저장, 비밀번호·관심사 변경, 로그아웃·물리 탈퇴.
- 회원가입은 이름과 필수 닉네임을 별도로 입력한다. 다른 회원에게는 닉네임을 표시한다.
- 내 글/내 댓글은 실제 이동 화면과 “목록 기능을 준비 중입니다” 안내까지만 구현한다. 조회 DB/API는 후속 작업이다.
- 앱 설정은 진입/복귀 화면까지만 구현하며, 세부 설정과 하단 탭·추가 아이콘은 범위 밖이다.
- 홈의 일반 관심사/로그아웃 버튼은 이동하고, 관심사 복구용 CTA는 유지한다.
- 관심사 저장은 진입한 내 정보 화면으로 복귀한다.

## 인증·기기 저장 계약

- Access JWT에는 sid를 포함하고 발급 유효기간은 15분(세션 만료 시각 이내). 매 보호 요청에서 세션·사용자 상태를 확인한다.
- 로그인 세션과 Refresh는 최초 로그인부터 30일 고정이며, Access도 세션 만료를 넘겨 사용할 수 없다.
- Refresh는 보안 난수 32바이트의 Base64url 43자 문자열. 서버에는 SHA-256 해시만 저장하고 발급/사용 이력을 연결한다.
- 갱신마다 Refresh를 교체한다. 사용한 Refresh 재사용은 해당 로그인 세션을 종료하고 그 commit을 확정한 후 401을 반환한다.
- 비밀번호 변경은 현재 세션/토큰을 유지하고 다른 세션을 종료한다. 원래 30일 만료를 연장하지 않는다.
- 동시 갱신은 하나의 작업을 공유하며 원래 보호 요청은 최대1회 재시도한다.
- 일반 통신 장애는 정보를 보관하고 재시도를 안내한다. 명확한 인증 무효는 로컬 인증을 정리한다.
- 교체 응답 유실/새 토큰 저장 실패 등 갱신 상태 불명확은 재로그인하며 이전 Refresh를 자동 재전송하지 않는다.
- SecureStore 한 묶음에 READY/REFRESHING/TERMINATING을 저장한다. 새 토큰 저장이 확인되기 전 요청을 재개하지 않는다.
- 인증 회차와 직렬 저장으로 이전 계정의 늦은 응답/401/IO 오류가 현재 계정에 영향을 주지 않게 한다.
- 로그아웃 시 조회·변경 캐시를 함께 삭제한다. 변경 캐시에 남던 비밀번호 입력도 제거한다.
- 서버 요청 실패에도 기기 정리에 성공하면 로컬 로그아웃하고 서버 종료 미확인을 안내한다. 기기 읽기/삭제 실패는 보호 접근을 차단하고 복구를 안내한다.
- 사진은 공통 인증 클라이언트를 거쳐 메모리에 표시한다. 다른 origin/URL 자격증명 및 오래된 요청의 토큰 사용을 차단한다.

## API

공통 prefix는 /api이며, 기존 CommonResponse와 errors/reason 형식을 사용한다.

| 메서드 | 경로 | 동작 |
| --- | --- | --- |
| POST | /auth/signup | 이름/닉네임/비밀번호 가입, 세션과 토큰 쌍 발급 |
| POST | /auth/login | 로그인별 세션과 토큰 쌍 발급 |
| GET | /auth/session | 사용자·세션·관심사 진입 상태 |
| GET | /auth/check-nickname | 가입 닉네임 중복 확인 |
| POST | /auth/refresh | Refresh 교체 및 새 토큰 쌍 |
| POST | /auth/logout | 해당 로그인 세션 종료 |
| GET | /users/me | 내 프로필 |
| GET | /users/me/check-nickname | 현재 회원을 제외한 닉네임 확인 |
| PATCH | /users/me/nickname | 닉네임 저장 |
| PUT/DELETE | /users/me/profile-image | multipart 사진 저장/기본 복구 |
| GET | /users/{user_id}/profile-image/{image_id} | 현재 참조 사진 보호 조회 |
| PUT | /users/me/password | 비밀번호 변경·다른 세션 종료 |
| POST | /users/me/withdrawal/verify-password | 탈퇴 비밀번호 사전 확인 |
| POST | /users/me/withdrawal | 최종 비밀번호 재검증·물리 탈퇴 |

로그인/가입/갱신은 access_token, refresh_token, token_type, access_expires_at, refresh_expires_at을 반환한다. 세부 스키마는 실행한 OpenAPI 및 backend/app/schemas에서 확인한다.

## Migration·실행 설정

- Revision b7f2c81d9e04, 이전 a4d7c9e21f3b.
- 새 표: auth_sessions, auth_refresh_tokens, profile_image_cleanup_jobs. 프로필 닉네임 비교 키/유일성 등 추가.
- 중복·잘못된 닉네임·예상하지 않은 계정 상태를 사전 검사해 중단한다. MariaDB DDL 중단 후 재개·백필 재실행을 지원한다.
- 실제 운영 전환은 승인된 점검 시간에 백업/사전 검사 → Migration → 영구 사진 경로/권한 확인 → API/앱 동시 전환 → 재로그인 검증 순서로 별도 수행한다.
- 기존 Access에는 sid가 없으므로 전환 후 기존 회원도 한 번 재로그인한다. 구형 가입 클라이언트에는 필수 nickname이 없어 새 계약과 동시 전환이 필요하다.
- 이 브랜치를 업로드하는 과정에서 실제 운영/기존 미리보기 DB 변경이나 배포는 수행하지 않는다.
- PROFILE_IMAGE_ROOT는 절대 비공개 저장 경로. 로컬 기본 backend/var/profile-images는 Git 제외.
- Docker 기본 구성은 /var/lib/trend-leader/profile-images의 named volume을 선언한다.
- MAINTENANCE_ENABLED는 기본 false. 기본 Docker 구성은 true를 전달한다. 배포 시 실행 주체/DB 권한을 확인한다.
- 실행기는 사진 정리를 60초마다, 만료 인증 기록을 한국시간03시에 정리하며 시작 시 catch-up을 수행한다.
- 종료된 인증 이력도 원래30일 만료까지 보관하고, 탈퇴 때는 즉시 연결 삭제한다.

## 검증

최신 업로드 전 검증 결과를 여기에 기록한다.

- 서버: 2026-11-14 전체 811 passed (실제 MariaDB 통합 포함).
- 앱: 2026-11-14 정식 타입 검사 통과, 전체 Jest 27 suites / 187 passed.
- 정적/공백: Ruff check app/tests/전환 검증 스크립트, git diff --check 통과.
- 격리 DB: MariaDB12.3.2의 localhost:3308/trend_leader_test에서 최종 전체 회귀. 기존 휴대폰 DB3307·미리보기 DB 제외.
- 최초 재실행은 기본 카테고리가 있는 휴대폰 DB와 빈 DB 전제 테스트가 충돌(779 passed/32 failed)했다. 3307 데이터를 삭제하지 않고 사용자 승인한 3308 빈 DB를 별도로 구성해 811개 전체 통과를 확인했다.
- 이전 DB 검증: 부분 DDL 중단/재개, 사전 충돌 차단, NFC/임시 닉네임·최종 제약, 반복 백필 유지.
- 전체 회귀용 빈 DB는 docker-compose.check.yml을 사용한다. 개인 .env.test.compose를 지정하고 docker compose --env-file .env.test.compose -p trend-leader-check -f docker-compose.check.yml up -d db-check로 실행한다.
- 전체 pytest 실행 시 TEST_DATABASE_URL과 DATABASE_URL을 localhost:3308/trend_leader_test로 함께 지정하고 테스트용 JWT_SECRET_KEY를 비공개 환경변수로 전달한다. 실제 환경파일/키는 커밋하지 않는다. 카테고리/사용자 seed를 전체 검사 DB에 넣지 않는다.
- 계정 통합 fixture는 localhost/127.0.0.1의 trend_leader_test 및 포트3307/3308만 허용한다. 기존 3307 전환 시뮬레이션 스크립트의 빈 DB 검사는 그대로 유지했다.
- 파일/서버: 부분 쓰기·commit 전 실패·응답 유실·삭제 재시도·현재 파일 보호, 동시 Refresh/닉네임/비밀번호 변경, 탈퇴/재가입.

### 남은 수동 확인

- 같은 세션에서 새 가입→탈퇴→로그인 거부→ID/닉네임 재사용의 휴대폰 확인.
- 다른 기기의 로그인 종료(서버 통합 테스트는 통과).
- 갤러리 취소/권한 거부, 닉네임 팝업의 취소/미저장 폐기·저장 중 닫기 차단 등 기기 예외.
- 기기 저장 읽기/삭제 실패·Refresh 중간 상태의 실제 기기 fault 확인(자동 실패 테스트 통과).
- 프로젝트 고유 새 native build/설치. 현재 검증은 Expo Go이며 빌드 통과를 의미하지 않는다.
- SDK57 권장 패치 차이는 보고했고 사용자 선택으로 현재 버전을 유지한다.
