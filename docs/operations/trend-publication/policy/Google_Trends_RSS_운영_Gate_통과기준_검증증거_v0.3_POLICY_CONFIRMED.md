## 0. 사용자 결정 및 운영 경계

### 확인된 사용자 결정

- **Q1 MVP-A**: 11월 중순 MVP는 자체 작성 또는 이용 권리를 확인한 트렌드 데이터 기반으로 진행한다. Google RSS 회신·권한 미확정이 MVP 전체를 막지 않도록 분리한다.
- **Q2 콘텐츠-A**: 앱은 자체 작성한 트렌드 제목·설명과 개별 검토한 외부 기사 원문 링크를 기본으로 사용한다. 기사 원문 제목·본문·이미지의 복제를 MVP 필수 조건으로 삼지 않는다.
- **Q3 일괄 게시**: 모든 Trend를 개별 검증하고, 검증·승인된 적격 항목만 Batch에 묶어 게시한다. 개별 검증을 묶음 처리로 생략하지 않는다.
- **Q4 승인 책임 B안**: 일반 콘텐츠는 기능 담당자가 개별 검증·승인한다. 고위험 분류가 의심되면 팀원 공동 검토로 분류와 근거를 확인한다.
- **Q5 고위험 처리 A안**: 11월 MVP에서 고위험 판정이 유지된 콘텐츠는 **원칙적으로 게시 제외**한다. 공동 검토는 고위험 콘텐츠를 게시하도록 예외 승인하는 절차가 아니다. 분류 오류가 입증되면 일반 검증 경로에서 재검토한다.
- Google의 자동 요청·영속 저장·자동 게시 권한은 여전히 **미확정**. 회신을 받지 못했다고 사용자 보고했으나, 메일 원문·회신 상태를 이 작업에서 별도로 확인하지 않았다.

### 적용 프로필

| **COMMERCIAL** | 향후 수익화·광고·상업 운영 | Post-MVP | 기존 승인 범위가 상업적 사용을 포함하는지 별도 명시 검증. 불명확하면 HOLD |

## 1. Gate 공통 판정 규칙

| 판정 | 정의 | 기록 기준 |
|---|---|---|
| PASS | 해당 행위·데이터 필드·환경·공개 범위에 필요한 조건을 모두 충족하고 독립적인 증거가 있음 | 충족한 AC(수용 기준)와 Evidence ID, 책임자, 날짜 필수 |
| HOLD | 중요한 이용 권한 또는 필요한 시스템 통제가 미확인 | 누락된 증거, 확인 담당자, 다음 확인 행동 기재 |
| FAIL | 적용 가능한 금지·제한에 저촉되거나 검증에서 실제 실패 | 위반 조건과 차단·회수 절차 기록 |
| N/A | 해당 행위가 설계/실행 경로에 존재하지 않음을 입증 | N/A 근거(구성·테스트·데모 검토), 적용 프로필, 재검토 조건 기재 |

**기본 정책**: 증거 없는 PASS 금지. 무응답은 동의가 아님. 기술적으로 동작한다는 사실도 법적 허가가 아님. Google 승인만으로 제3자 언론사 권리를 충족했다고 볼 수 없음. 출처 표시만으로 저장·게시 권한을 대체할 수 없음.

**권한 근거의 자격**: (1) 해당 행위에 실제 적용되는 공식 정책 문서의 명시 규정 또는 (2) 권한 있는 주체의 범위가 구체적인 회신·허가 또는 (3) 특정 행위를 허용하는 명확한 법적 근거를 기록. 애매한 문구, 공식 FAQ의 단순 기술 지원 안내, 일반적 추정은 PASS 근거가 아님. 개별 회신의 권한·적용 범위도 확인.

**검증 증거 원칙**: 각 자료에는 문서 제목, 정확한 URL, 조회일·유효일(해당 시), 보존 위치 또는 식별자, 발췌한 관련 조항, 근거가 허용하는 행위, 해석의 한계, 담당 검토자, 재검토 트리거를 명시. 정책 원본과 해석 메모를 혼동하지 않음.

**승인 수준 구분**: `G6 운영 프로필 승인`(운영 경로·통제 절차 자체의 승인), `G4 개별 Trend 검증·담당 승인`(콘텐츠 적격성), `Batch 게시 실행`(이미 승인된 항목의 일괄 반영)을 혼동하지 않는다. **G6 PASS가 이후 모든 Trend의 자동 게시 허가를 뜻하지 않으며**, Batch를 실행할 때마다 G6 전체를 반복 승인하는 것도 아니다. 승인·검증 시점의 내용이 변경되면 해당 Trend만 재검증한다.

## 2. 운영 Gate G0~G6 — 상세 수용 기준

### G0. 데이터 원천·목적·필드 범위 확정

- **PASS 조건**
  - 소스별로 `데이터 출처/획득 경로/행위(읽기·요청·저장·가공·공개)/데이터 필드/이용 목적/이용자 범위/비상업 여부/보존 기간/담당자`를 정의한다.
  - Google RSS를 이용한다면 정확한 대상 URL과 운영 방식·예상 주기를 문서화한다. **주기는 기술 요구로만 제안**하며 Google이 허용하는 한도라고 추정하지 않는다.
  - MVP-A에서는 단일 샘플 트렌드에 대해 '어떤 사실을 어떤 경로로 확인했는지' 및 링크 검토 방식이 추적된다.
- **증거**: `E-G0-01 Source Scope Sheet`, `E-G0-02 Field Inventory`, `E-G0-03 샘플 트렌드 출처 추적표`.
- **HOLD/FAIL 트리거**: 출처 불명, 유입 경로가 혼합되어 소스 분리가 불가능, 콘텐츠 필드 및 공개 범위 미정.
- **책임 후보**: 콘텐츠/도메인 설계 담당 초안 작성 → 팀 검토.

### G1. Google RSS 자동 접근 권한

- **PASS 조건 (RSS-OPS 전용)**
  - 정확한 Google Trends RSS URL에 적용되는 약관, 서비스별 규정 및 자동 접근 관련 기계 판독 지시를 확인하고 증거를 남긴다.
  - **반복적인 서버 자동 요청 자체**가 계획한 방식·주기로 허용됨을 명확히 뒷받침하는 근거가 있다. 공개 문서만으로 특정 범위를 결정하기 어려우면 추가 확인·허가가 필요하다.
  - 요청 횟수·실패 시 재시도·차단 시 중단 등의 운영 조건이 허가 범위와 충돌하지 않는다.
- **증거**: `E-G1-01 정책 조항 스냅샷`, `E-G1-02 적용 범위/접근 지시 검토 기록`, `E-G1-03 반복 접근 허용 근거 또는 범위가 구체적인 공식 회신`, `E-G1-04 운영 요청 정책`.
- **N/A (MVP-A)**: 라이브 Google RSS를 요청하는 코드 경로·스케줄·배포 설정을 사용하지 않음을 정적 점검 및 실행 시나리오로 확인한다.
- **HOLD/FAIL 트리거**: 단순 RSS 내보내기 지원만 증명됨, 적용 약관 불분명, 명시된 접근 제한 위반, 허가 범위 밖 호출.
- **주의**: Google Trends 도움말의 '평균 10분마다 데이터 갱신'은 **Google 서버의 데이터 갱신 설명**이지 외부 수집기에게 10분 폴링을 허용하는 규정이 아니다.

### G2. Google 데이터 DB 저장·보관·정규화 권한

- **PASS 조건 (RSS-OPS 전용)**
  - 각 필드(검색어, 트렌드 수치·시각, 관련 기사 메타데이터, RSS XML 원본)를 **개별 행위별**로 심사한다: 저장, 갱신, 중복 제거, 자체 정규화, 분류, 장기 누적 및 삭제.
  - 각 필드의 허용·제외 여부, 보존 기간, 삭제 의무, 허용된 가공 범위가 근거와 함께 정리되어 있다.
  - 법적 근거와 구현 설정(저장 대상 필드, TTL/보존 규칙, 삭제 경로)이 일치한다.
- **증거**: `E-G2-01 필드×행위 권리 매트릭스`, `E-G2-02 보존·삭제 정책`, `E-G2-03 허용 범위 확인서`, `E-G2-04 합성 데이터 기반 저장·삭제 계약 테스트`.
- **N/A (MVP-A)**: Google RSS 원본·파생 데이터가 DB/로그/개발 Seed/앱 응답에 섞이지 않았음을 확인.
- **HOLD/FAIL 트리거**: 원본 저장 허가를 근거로 장기 보관까지 확장, 보관 기간 미확정인데 영속 누적, 제한 필드를 로그·캐시에도 저장.
- **주의**: Google APIs 약관 Section 5(e)는 API 반환 콘텐츠의 영구 복제/DB 구축 등에 제한을 두지만, **해당 RSS에 그 약관이 적용되는지는 미확인**이다. 따라서 직접적 RSS 금지 조항이라고 단정하지 않음.

### G3. 앱 공개 표시·재게시·출처 표시 권한

- **PASS 조건 (RSS-OPS 전용)**
  - Google RSS에서 획득한 데이터 또는 그 정규화·분류 결과를 **모바일 앱 일반 사용자에게 공개할 수 있는 범위**가 확인되어 있다.
  - Google 출처를 필요한 위치에 인용하며, Google이 Trend Leader의 제휴·후원·인증기관인 듯 오인시키지 않는다.
  - 공개 허용 필드와 API 응답 필드/화면 표시 필드를 상호 대조한다. 허용되지 않은 기사 제목·원문·이미지가 응답에 포함되지 않는다.
- **증거**: `E-G3-01 공개·재이용 허용 근거`, `E-G3-02 API 필드 매핑`, `E-G3-03 모바일 Source Card 화면 QA`, `E-G3-04 출처 표시 검토 기록`.
- **N/A (MVP-A)**: 공개된 Trend가 Google RSS에서 파생된 것이 아니며, 자체 콘텐츠에 Google의 공식 데이터라는 오인 표시가 없음을 확인.
- **HOLD/FAIL 트리거**: 데이터 내보내기 지원만으로 재게시를 허용했다고 판정, 승인되지 않은 필드 노출, 후원·제휴 암시.

### G4. 제3자 언론사 권리 및 MVP 콘텐츠 품질

- **PASS 조건 (MVP-A 및 RSS-OPS)**
  - **운영 절차 수준**: 개별 Trend의 검증·위험 분류·담당자 승인·제외·재검증 기준과 증거 양식을 마련한다. 이 절차가 PASS여도 아직 등록되지 않은 콘텐츠까지 승인한 것은 아니다.
  - **개별 Trend 수준**: 제목·설명은 자체 작성하고, 근거 출처와 작성·검토 주체를 확인한다. 개별 기사 링크가 실제 원문으로 연결되며 링크 방식/게시 맥락의 문제를 검토한다. 링크만 사용한다고 모든 법적 문제가 면제되는 것은 아니다.
  - 기사 원제목, 본문, 이미지, 썸네일, 언론사 제공 요약을 MVP에서 복제하지 않는다는 **제외 범위**를 화면·데이터에서 확인한다.
  - 개별 Trend를 **일반·적격 / 고위험 / 증거 부족 / 권한 없음**으로 분류하고, 일반·적격 항목에 한해 기능 담당자가 개별 승인한다.
  - **고위험 의심 항목**은 팀 공동 검토로 위험 분류와 근거를 확인한다. 고위험 판정이 유지되면 11월 MVP에서 제외한다. 고위험이 아님을 근거로 확인한 경우에는 일반·적격 검증 절차로 되돌린다. 공동 검토만으로 권한 없는 자료를 게시할 수는 없다.
  - **증거 부족**은 HOLD 후 보완·재검증하고, **권한 없음**은 게시 차단한다. 사건사고·실명 인물·명예·개인정보 등 민감 트렌드와 정정·공개중단 요청을 별도 점검한다.
- **증거**: `E-G4-01 개별 Trend 검토 카드`, `E-G4-02 원문 URL 검토 기록`, `E-G4-03 원문 복제 제외 체크`, `E-G4-04 정정·이의제기 처리 규칙`, `E-G4-05 위험 분류·담당 승인/공동 검토 기록`.
- **HOLD/FAIL 트리거**: 출처 없는 사실 주장, 원문 무단 복제, 열리지 않는 링크, 이용 권리·진위성 미검증, 고위험 판정 유지·증거 부족·권한 없음에도 게시 승인.
- **권리 구분**: 단순 사실과 표현의 법적 보호 여부는 별도 평가 대상이다. Google의 권리와 언론사 저작권은 서로 독립.
- **불변조건**: `개별 검증 통과 ∧ 일반·적격 분류 ∧ 담당자 승인`을 만족하는 Trend만 Batch 게시 후보가 된다.

### G5. 기술적 중단·차단·회수·기록 검증

- **PASS 조건 (배포되는 경로에 적용)**
  - 비승인 데이터의 **요청·쓰기·공개가 차단**됨을 테스트 결과로 확인한다. Google RSS-OPS는 허가 전 활성화 금지.
  - **Batch에 포함되는 모든 Trend**가 개별 검증·담당 승인을 완료했는지 게시 직전에 재확인한다. 검증 당시의 제목·설명·원문 링크·출처 등 승인 대상 내용이 바뀌었다면 해당 Trend만 재검증 전까지 제외한다.
  - **부분 부적격·부분 실패**가 발생하면 해당 항목을 식별하여 보류·오류 기록을 남기고, 나머지 적격 항목만 게시 가능하도록 한다. 다만 실제 DB Transaction의 원자성·부분 성공 구현 여부는 현재 코드 검증 후 별도 확정하며, 여기서는 정책 동작만 정의한다.
  - 문제가 발견되면 적어도 **신규 수집 중단 → 신규 게시 차단 → 기존 공개 비노출 → 저장 데이터 보존/삭제 의무 검토**가 가능한 운영 절차가 있다. 게시 이후에도 개별 콘텐츠 공개중단/재게시 방지 경로를 확인한다.
  - Batch 식별자, 포함/제외 Trend, 검증·승인 내용의 식별값, 담당자, 승인·게시 시각, 항목별 성공/실패/보류 결과를 추적한다. 감사 로그에 권한 없는 원문 콘텐츠를 복제하지 않는다.
  - 실제 운영 승인 시 스케줄, 요청 한도, 재시도·오류 응답, 중단 스위치의 조건과 테스트 절차를 확정한다.
- **증거**: `E-G5-01 차단 테스트 기록`, `E-G5-02 배포 설정/비활성 스케줄 점검`, `E-G5-03 공개중단·삭제 리허설`, `E-G5-04 로그와 노출 필드 점검`, `E-G5-05 Batch 승인 대상 대조 기록`, `E-G5-06 항목별 게시 결과/변경 방어 검증`.
- **HOLD/FAIL 트리거**: 차단 설정 없이 운영 코드 활성화, 권리 철회 후에도 게시 유지, 오류 재시도가 제한을 우회, 미승인·변경된 Trend의 혼입·노출, 개별 공개중단 불능.
- **현재 단계**: 테스트 이름과 기대 결과를 설계할 수 있으나 **코드 미검증·실행 미수행**. PASS 판정 금지.

### G6. 최종 운영 승인 및 감사 기록

- **PASS 조건 — 운영 프로필 자체의 승인**
  - 해당 경로의 필수 Gate가 PASS이며, N/A에는 증명이 있고 HOLD/FAIL은 해소됨.
  - 허용되는 URL·필드·행위·보존·공개 범위·비상업/상업 구분, 정책 버전 및 재검토 시점을 명시한다.
  - 팀이 지정한 **운영 프로필 최종 승인자**가 증거에 근거해 승인 날짜와 배포 범위를 기록한다. *기능 담당자에게 개별 Trend 승인 권한을 부여하는 B안 결정*은 **G6 최종 승인자 개인의 지정과는 별개**다.
  - 실서비스 공개 전 기사 오류·권리 침해 신고에 대한 연락/정정/삭제 대응 주체를 결정한다.
  - **G6 운영 프로필 승인 ≠ 개별 Trend 승인 ≠ Batch 게시 실행**임을 문서와 운영 기록에 구분한다. 새 Batch마다 G6 전체를 재승인하지 않지만 이용 범위·권한 조건·운영 통제가 바뀌면 관련 Gate를 재검토한다.
- **증거**: `E-G6-01 운영 프로필 승인 체크리스트`, `E-G6-02 최종 결정 기록(승인자·범위·시각)`, `E-G6-03 근거 인덱스`, `E-G6-04 운영 재검토 일정 및 변경 감시 기준`, `E-G6-05 콘텐츠 승인 책임 및 배치 게시 위임 범위`.
- **HOLD/FAIL 트리거**: 실제 G6 승인자 미지정, 근거 없는 PASS, 운영 승인과 콘텐츠 승인의 혼용, MVP/상업 범위 혼용, 권리 변경에 대한 재검토 계획 없음.

## 6. 각 경로의 통과 결정 규칙

### MVP-A 출시/시연 Gate

`G0 PASS ∧ G4 절차 PASS ∧ G5 통제 PASS ∧ G6 운영 프로필 PASS ∧ (G1,G2,G3: Google RSS 비이용 N/A 입증) ⇒ MVP-A 운영 프로필 진입 검토 가능`

`개별 G4 검증 PASS ∧ 일반·적격 판정 ∧ 기능 담당자 승인 ∧ 승인 대상 콘텐츠 변경 없음 ⇒ 해당 Trend의 Batch 게시 후보 자격`

- **운영 프로필 승인과 콘텐츠 적격성은 모두 필요**하다. G4 절차 PASS를 향후 모든 Trend에 대한 포괄 승인으로 취급하지 않는다.
- Batch 게시 직전 개별 승인 및 내용 동일성을 확인한다. 출처 불명·고위험·권한 없음·원문 복제·변경된 카드는 **해당 카드만 보류/제외**하고 나머지 적격 항목은 게시 가능하도록 한다.
- MVP-A에서 Google RSS 자동 요청·저장·게시를 사용하지 않는다는 증거가 N/A의 필수 전제다.
- 여기서 'Batch 게시 가능'은 **운영 정책상의 자격**을 뜻한다. 실제 시스템에서 항목별 결과를 분리할 수 있는지와 DB Transaction 경계는 구현 검증 전까지 미확정이다.

### Google RSS 실제 운영 Gate

`G0~G6 전부 PASS ⇒ 허용받은 정확한 범위에 한하여 운영 검토 완료`

- Google 서면 회신이 오더라도 자동으로 전체 PASS가 되지 않음: 자동 접근, 저장, 공개, 제3자 권리, 운영 통제는 독립.
- 기사 메타데이터가 허용되지 않았다면 그 필드를 제외해 **축소 운영** 가능 여부를 다시 심사한다.
- 회신 없음 / 모호함 / 적용 주체 불명확 ⇒ HOLD, 실제 수집·저장·게시 운영 불가.
- 비상업 승인이라고 해서 상업 전환 권한까지 부여된 것으로 판단하지 않는다.

## 7. 운영 사고·정책 변경 시 재검토 조건

- Google 회신 도착, 약관 개정, 서비스별 추가 조건 확인, 자동 접근 지시 변경.
- 수집 빈도/엔드포인트 변경, 수집 필드 추가, 원본 XML 보관 또는 장기 시계열 분석 도입.
- 기사 제목/이미지/AI 요약을 표시하거나 외부 AI에 원문을 전달하도록 범위 확장.
- MVP 데모에서 일반 공개 서비스, 또는 비상업에서 광고/수익화로 전환.
- 링크 대상의 정정·삭제·분쟁 또는 권리자의 게시 중단 요청.
- 관련 데이터의 출처가 불명확해지거나 소스 간 데이터가 혼합되는 현상 발견.

권고 운영 원칙: **중요한 조건 변경 시 변경된 범위에 대한 PASS를 자동 승계하지 않고, 우선 HOLD로 재평가한다.** Google 데이터가 실제 저장된 이후라면 기존 공개·보존의 중단·삭제 의무도 함께 검토한다.

## 9. 사용자 결정 확정 및 남은 실무 지정

### 정책상 결정 완료

1. **11월 MVP 데이터·기사 표시**: 자체 작성·권리 확인 데이터와 자체 설명·검토한 원문 링크(A안).
2. **게시 승인 단위**: 개별 G4 검증 후 적격 Trend를 묶은 **Batch 게시**.
3. **콘텐츠 승인 책임**: 기능 담당자 승인 + 고위험 의심 항목 팀 공동 검토(**B안**).
4. **고위험 처리**: 고위험 판정 유지 시 11월 MVP **원칙적 제외(A안)**. 공동 검토의 목적은 위험 분류 확인이며 고위험 게시 예외 승인이 아님.
5. **Google RSS 실데이터 운영**: 별도 권한과 운영 Gate가 확인되기 전까지 HOLD. P0~P3 FROZEN 기술 PoC는 변경하지 않음.

### 아직 지정·검증되지 않은 사항(정책 선택을 다시 묻는 대상 아님)

- 실제 **기능 담당자 및 G6 운영 프로필 최종 승인자**의 이름/역할 지정, 사고 시 공개중단·삭제 담당자 및 연락 경로.
- Batch 게시 전 기록을 실제로 어느 문서·도구에 보관할지, 검증 대상 내용의 변경을 어떤 방식으로 식별할지(현행 코드/DB 조사 후 결정).
- G0~G6의 근거·개별 Trend 심사 증거·AT-01~AT-16 실행 결과. 미실행 조건은 PASS 처리하지 않는다.

## 11. v0.2 → v0.3 변경 요약 및 비변경 범위

- **변경**: 사용자 결정 3건(Q3 일괄 게시, Q4 B안 책임 분리, Q5 고위험 A안 제외) 반영. G4의 절차/개별 검증 분리, G5의 Batch 게시 전 대조·변경·부분 실패 통제, G6의 운영 승인과 콘텐츠 승인의 분리.
- **추가**: E-G4-05, E-G5-05~06, E-G6-05, Batch 논리 기록 필드, AT-10~AT-16. 기존 AT-01~AT-09의 핵심 의도 유지.
- **수정**: 감사 예시에서 기사 원제목 `source_title` 필수 보관을 제거하고 승인 대상의 참조값 `content_ref`로 대체.
- **보존**: Google RSS 실운영 HOLD, G0~G3 판정 원칙, 제3자 권리 검증, 비상업/상업 분리, P0~P3 FROZEN 기술 PoC 및 실제 코드/DB/API 계약 **변경 없음**.
- **검증 한계**: 공식 Google 근거를 재열람했으나 실제 Google 회신·실제 프로젝트 코드·FROZEN 계약 전문·테스트 실행 결과는 이번 문서 작성에서 확인되지 않음. 미확정 사항을 추측하여 PASS 처리하지 않음.

> 이 문서는 **사용자가 확정한 내부 운영 정책**을 기록한 것이며, 법률 자문 또는 Google/언론사에 의한 허가 문서가 아니다. 확정되지 않은 권한은 실제 운영에서 사용하지 않는다. 실제 게시·운영 승인 여부는 별도 Gate 증거 및 검증 결과에 따른다.
