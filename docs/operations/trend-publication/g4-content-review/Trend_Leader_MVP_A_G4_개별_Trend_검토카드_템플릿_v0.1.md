## D. 항목별 G4 검토 체크리스트

- [ ] 게시할 제목과 설명이 자체 작성됐고 근거와 일치한다.
- [ ] 사실관계를 검증할 수 있는 근거와 확인 일시가 있다.
- [ ] 원문 링크가 실제로 열리고 의도한 대상 페이지로 연결된다.
- [ ] 해당 링크 및 출처 표시 방식에 문제되는 사유를 발견하지 않았다.
- [ ] 원문 기사 제목·본문·이미지·제공 요약·자동 썸네일을 무단 복제하지 않는다.
- [ ] Google RSS 파생 데이터나 승인되지 않은 다른 외부 데이터가 포함되지 않았다.
- [ ] 개인정보·명예훼손·루머·사회적 민감성 위험을 검토했다.
- [ ] 필요한 권리·약관·이용 근거를 확인했다.
- [ ] 게시 전 기록과 승인 대상 콘텐츠의 버전(참조값)을 연결했다.

## E. 위험 분류 및 처리

다음 중 **하나**를 선택한다.

| 위험 분류 | 판정 조건 | MVP-A 처리 |
|---|---|---|
| `GENERAL_ELIGIBLE` | 사실·권리·링크 검증 완료, 고위험 아님 | 기능 담당 승인 가능 |
| `HIGH_RISK` | 인물 의혹·분쟁·민감 정보 등 고위험 판정 유지 | 팀 공동 검토 후 **MVP에서 제외** |
| `INSUFFICIENT_EVIDENCE` | 출처·진위·링크·보관 근거 중 필요한 증거 부족 | HOLD, 근거 보완 후 재검증 |
| `NO_PERMISSION` | 필요 권한이 부재하거나 적용되는 금지·제한에 저촉 | 게시 차단; 공동 검토로 권한 대체 불가 |

- 위험 분류: `<위 4개 중 하나>`
- 핵심 근거: `<2~3줄>`
- 공동 검토 필요 여부: `예 / 아니요`
- 공동 검토 참여자·시각·결론: `<해당 시 작성>`
- 고위험 분류가 정정되었다면 그 근거: `<정정 사유와 새로운 증거>`

## H. 사용 방법

1. 실데이터가 아니라면 합성·가상 샘플임을 크게 표시한다. 실데이터와 시연 데이터를 섞지 않는다.
2. 카드 1개는 **Trend 1건**만 검토한다. 여러 건을 대표 카드 1개로 승인하지 않는다.
3. 일반 콘텐츠는 기능 담당자가 최종 승인한다. 다른 팀원의 일반 콘텐츠 교차 검토는 권장할 수 있지만 매 건 필수로 강제하지 않는다.
4. 고위험 의심 콘텐츠는 두 팀원이 함께 위험 분류를 검토한다. 고위험 판정 유지 시 MVP 게시 제외이며 공동 검토가 예외 승인으로 작동하지 않는다.
5. 개별 G4 검증 후 Batch 장부의 `review_evidence_id` 및 `content_ref`에 연결한다.
6. **문서에서 PASS를 선택했다고 실제 코드가 통제 기능을 갖춘 것은 아니다.** G5 동작 검증과 G6 운영 승인이 별도로 필요하다.
