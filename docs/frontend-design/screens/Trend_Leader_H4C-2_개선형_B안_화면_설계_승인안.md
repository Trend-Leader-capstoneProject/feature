## 1. 문제 및 목표

현재 홈 상단에 크고 동일하게 강조된 `관심사 수정하기`/`최신 트렌드 보기` 버튼 두 개, 별도 로그아웃 버튼이 배치되어 첫 개인화 카드의 화면 진입 위치가 낮다.

**목표:** 홈에 진입한 사용자가 `관심사 맞춤 트렌드`를 가장 중요한 콘텐츠로 인식하게 하되, 관심사 수정·전체 최신 목록·로그아웃 기능의 접근성을 보존한다. 시각적 밀도를 개선하되 데이터/인증/Navigation 계약은 변경하지 않는다.

## 2. 팀 승인 정보 구조 — 개선형 B안

```text
┌─────────────────────────────────────┐
│ Trend Leader              로그아웃  │  ← 별도 메뉴 없는 보조 액션
│ [사용자명]님, 관심 분야의 최신...    │
│                                     │
│ 관심사 맞춤 트렌드   [관심사 수정]    │  ← 섹션 설정용 액션
│                      전체 최신 보기 ↗│  ← 목록 시작 전에 항상 접근
│                                     │
│ ┌─────────────────────────────────┐ │
│ │ 기존 TrendCard #1               │ │
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ 기존 TrendCard #2               │ │
│ └─────────────────────────────────┘ │
│                 ...                 │
└─────────────────────────────────────┘
```

위 도식은 상대적 배치·강조 정책만 의미한다. 정확한 dp 값, 텍스트 줄바꿈, 배경·테두리 표현은 디자인 시스템 후보 토큰을 사용해 실기기 검증 후 조정한다.

- **헤더**: `Trend Leader`와 기존 사용자 맞춤 안내 문구를 유지한다. 우측 `로그아웃`은 텍스트형 보조 Pressable로 전환한다. 별도의 설정/계정 메뉴를 신설하지 않는다. 화면에 보인 톱니바퀴는 Expo 개발 UI로, 앱 기능이 아니다.
- **개인화 섹션**: `관심사 맞춤 트렌드` 제목을 시각적 중심으로 한다. 제목 옆 `관심사 수정`은 해당 섹션의 설정 액션이다.
- **전체 최신 목록 진입**: `전체 최신 보기`를 개인화 섹션과 첫 카드 사이에 가벼운 링크형 액션으로 제공한다. `ListFooterComponent` 또는 무한 목록 맨 끝으로 이동시키지 않는다.
- **카드**: 기존 `TrendCard`의 데이터, 순서, 카드 액션, 표시 규칙은 변경하지 않는다.
- **색상**: 큰 Primary 버튼 2개를 제거하고, 보조 액션에 기존 `colors`/`spacing`/`typography` 토큰을 우선 사용한다. 새로운 전역 디자인 토큰은 만들지 않는다.
- **안내문 밀도**: 기존 홈 안내 문구를 유지한다. 같은 뜻의 긴 섹션 부제목을 중복 추가하지 않는다.

## 3. 기능 연결 및 표시 정책

| 액션 | 시각 레이블 후보 | 접근성 이름(기존 테스트 계약 유지 권장) | 이벤트 |
| --- | --- | --- | --- |
| 로그아웃 | 로그아웃 | 로그아웃 | 기존 `handleLogout()` |
| 관심사 수정 | 관심사 수정 | 관심사 수정하기 | `navigation.navigate("InterestEdit")` |
| 전체 최신 | 전체 최신 보기 | 최신 트렌드 보기 | `navigation.navigate("LatestTrend")` |

시각 레이블과 접근성 이름을 다르게 둘 경우 스크린리더의 명확성이 유지되어야 한다. 실제 구현 시 테스트 선택자는 시각 문구에 불필요하게 결합하지 않도록 한다.

### UI 상태별 노출 규칙

| Main 상태 | 로그아웃 | 일반 관심사 수정 | 전체 최신 | 기존 상태 UI |
| --- | --- | --- | --- | --- |
| 최초 Loading | 유지 | 숨김(현행 정책) | 유지 | Loading 유지 |
| 정상 목록 | 유지 | 섹션 제목 옆 1개 | 유지 | 기존 FlatList / TrendCard |
| 정상 Empty | 유지 | 섹션 제목 옆 1개 | 유지 | Empty 안내 유지 |
| 일반 조회 오류 | 유지 | 가능(기존 정책) | 유지 | Retry 유지 |
| `INTERESTS_NOT_AVAILABLE` | 유지 | **숨김** | 유지 | 본문 복구 CTA `관심사 수정하기` **1개만** 유지 |
| `INTERESTS_NOT_INITIALIZED` | 유지 | 숨김 | 유지(기존 UI 계약) | Session 재검증/RootNavigator 복구 우선 |
| 401/로그아웃 전환 | 기존 인증 정책 | 변경 없음 | 변경 없음 | AuthProvider·RootNavigator 처리 |

`INTERESTS_NOT_AVAILABLE` 또는 초기화 검증 중에는 정상 개인화 카드가 있는 것처럼 보이지 않도록 기존 도메인 상태 UI를 우선한다. 상태별 `관심사 맞춤 트렌드` 제목 표현은 오류/검증 화면을 오인시키지 않는 방식으로 구현 시 점검한다.

## 4. 반응형·접근성

- Android **360~412dp** 세로 화면 우선 검증. 글자 확대 시 헤더 제목과 로그아웃, 섹션 제목과 관심사 수정이 겹치지 않아야 한다.
- 터치 가능한 `Pressable`은 시각적 텍스트 크기와 무관하게 **최소 44×44dp** 터치 영역을 확보한다.
- 제목 옆 컨트롤이 한 줄에 들어가지 않는 경우 텍스트를 무리하게 축소·잘라내지 않는다. 줄바꿈 또는 보조 액션의 아래쪽 배치를 허용한다.
- 로그아웃 처리 중 비활성화·중복 요청 방지·진행 상태 접근성·실패 Alert는 보존한다.
- 주요 액션에 `accessibilityRole="button"`, `accessibilityLabel`, 필요 시 `accessibilityState`를 적용한다.
- 색상만으로 탭/클릭 가능 여부를 표현하지 않는다. 링크형 최신 목록 진입점은 텍스트 및 배치로 상호작용 가능함을 나타낸다.
- 앱 내부 설정 아이콘을 신규 생성하지 않는다(기존 화면 우측 톱니바퀴는 Expo 개발용 오버레이).

## 5. 구현 경계 및 변경 대상

- 기본 변경 파일: `frontend/src/app/screens/PersonalizedMainScreen.tsx`.
- 기존 `renderHomeHeader()` 내 헤더 / 섹션 제목 / 보조 액션 재배치. `home-quick-actions` 테스트 ID는 가능한 유지하되, 변경된 DOM 계층에 맞추어 테스트를 점검한다.
- 화면에 목록이 있는 경우 기존 `FlatList.ListHeaderComponent={renderHomeHeader()}`를 유지한다. Empty/Error/Loading 시 기존 `!isScrollableHome` 헤더 분기를 유지하여 중복 헤더가 생기지 않도록 한다.
- `FlatList` 단일 스크롤 / `onEndReached` / Footer Retry / Pull-to-refresh 유지. 새 `ScrollView`, Bottom Tab, 설정 Route, 북마크, 검색, 추천 엔진 추가 금지.
- `TrendCard`, `usePersonalizedTrends`, `useUpdateInterests`, 인증·Cursor·API 계약의 기능 변경 없음.
- 기존 `PrimaryButton`을 전역 변경하여 해결하지 않는다. 홈 전용 보조 `Pressable` 표현을 우선 검토한다. `INTERESTS_NOT_AVAILABLE` 복구용 PrimaryButton은 유지한다.

## 6. 단계별 구현 및 검증

### H4C-2A — RED/계약 테스트

- 정상 목록에서 `Trend Leader`, 개인화 섹션 제목, 관심사 수정·전체 최신·로그아웃이 모두 제공되는지.
- 두 탐색 액션이 각각 `InterestEdit`·`LatestTrend`로 이동하며 로그아웃은 주요 탐색 영역과 분리되는지.
- Loading, Empty, Error 및 두 409 reason에서 액션의 노출 조건과 복구 CTA 중복 방지가 유지되는지.
- 로그아웃 중복 실행 방지/실패 복구 및 접근성 이름이 유지되는지.
- 색상/배치 변화 자체는 RNTL만으로 픽셀 완성 판정하지 않는다.

### H4C-2B — GREEN 및 회귀

- `renderHomeHeader()`의 레이아웃만 수정하고 테스트를 GREEN으로 만든다.
- 관련 화면 테스트 → 전체 Jest → `npm run typecheck` → `git diff --check`.
- 간헐적인 `PersonalizedMainCursorRecovery` Jest 5초 Timeout은 재발 시 별도 조사; 원인을 단정하거나 단순히 제한 시간만 늘리지 않는다.

### H4C-2C — Android Acceptance

- 동일 기기·텍스트 배율에서 변경 전/후 첫 화면을 비교한다. 첫 TrendCard가 위로 이동했는지, 기존 카드 가독성을 해치지 않는지 평가한다.
- 360~412dp, 긴 사용자명·한국어 텍스트·글자 확대 조건에서 버튼·제목 겹침을 확인한다.
- 세 진입점 터치, 정상/Empty/오류, 409 복구, 목록 스크롤·Pagination·Refresh 등을 확인한다.
- Expo 개발용 오버레이를 앱의 실제 기능 또는 결함으로 오인하지 않는다.

### H4C-2D — 문서 및 독립 커밋

- Screen Specification을 **Candidate 유지**하며 H4C-2 팀 승인 결정·구현 결과·실기기 검증 결과를 날짜 구분하여 반영한다.
- 오래된 문서 상단의 `MainPlaceholderScreen` 및 `B안 UI 리팩터링 미시작` 문구를 현재 상태와 구별해 갱신한다.
- FROZEN v1.1 기능 계약은 변경하지 않는다. 충돌이 발견될 때만 별도 변경 심사를 거친다.
- 사용자 검증·Diff 확인 후 `[feat/home] 개인화 홈 콘텐츠 우선 레이아웃 정돈` 같은 단일 의도 커밋을 권장한다.

## 7. 설계 상태 요약

**팀 승인:** 개선형 B안 정보 계층과 기능의 상대 배치.

**구현 이전 검증 필요:** 정확한 간격·너비·줄바꿈·색 대비·작은 화면에서의 최종 시각 디자인. 따라서 설계가 승인되었다고 해서 시각 구현까지 Frozen 또는 Acceptance 완료로 표현하지 않는다.

**미해결인 신규 기능 없음:** 기존 기능 연결만 재배치하며, 설정 페이지·검색·북마크·새 Bottom Tab은 본 작업 범위에서 제외한다.
