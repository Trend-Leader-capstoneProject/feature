## 1. 문서 목적

이 문서는 Trend Leader 전체 화면에 적용할 시각적 방향과 디자인 판단 기준을 정의합니다.

색상 HEX 값, 폰트 크기, 간격, radius와 같은 구체적인 구현 토큰은 이 문서에서 확정하지 않습니다. 해당 값은 이 아트 디렉션을 바탕으로 `design-system-snapshot.md`에서 정의합니다.

특정 화면의 정보 구조, API 응답 필드, Navigation, 컴포넌트 파일명과 비즈니스 정책도 이 문서의 범위에 포함하지 않습니다.

---

## 2. 서비스 정체성

Trend Leader는 단순 뉴스 앱이나 인기 검색어 순위 앱이 아닙니다.

사용자가 선택한 관심 분야를 기준으로 현재 떠오르는 트렌드를 발견하고, 트렌드의 배경과 흐름을 빠르게 이해하도록 돕는 개인화 트렌드 관측 도구입니다.

Trend Leader가 제공해야 하는 핵심 경험은 다음과 같습니다.

* 사용자의 관심 분야에서 발생하는 새로운 신호를 발견한다.
* 여러 출처에 흩어진 정보를 하나의 이해 가능한 흐름으로 정리한다.
* 트렌드의 현재 순위와 변화 방향을 빠르게 파악한다.
* 기본 요약과 AI 분석을 통해 트렌드의 의미를 이해한다.
* 필요한 트렌드를 저장하고 이후 다시 확인한다.

서비스는 사용자가 많은 콘텐츠를 소비하도록 유도하는 피드보다, 중요한 변화를 빠르게 판별하도록 돕는 관측 도구에 가깝게 표현되어야 합니다.

---

## 3. 디자인 명제

> 흩어진 트렌드 신호를 포착하고, 사용자가 이해할 수 있는 정보로 편집한다.

Trend Leader의 화면은 일반적인 콘텐츠 피드가 아니라 다음 두 성격의 중간 지점을 지향합니다.

* 편집 매거진의 명확한 정보 계층과 읽기 흐름
* 데이터 관측 도구의 변화 감지와 상태 표현

정보를 단순히 나열하지 않고, 사용자가 무엇을 먼저 보고 어떻게 해석해야 하는지가 시각적으로 드러나야 합니다.

---

## 4. 사용자가 받아야 하는 인상

Trend Leader는 다음 인상을 전달해야 합니다.

* 빠르게 변화하는 정보
* 새로운 흐름에 대한 관측과 발견
* 단순 수집이 아닌 편집된 정보
* 사용자의 관심사를 반영한 개인화된 시선
* 근거와 구조가 느껴지는 신뢰할 수 있는 분석
* 젊고 현대적이지만 가볍거나 유행에만 치우치지 않은 분위기

화면은 재미를 위해 정보를 장식하기보다, 복잡한 트렌드 정보를 명확하게 이해시키는 데 집중합니다.

---

## 5. 주요 시각 언어: Signal Editorial

Signal Editorial은 Trend Leader의 기본 시각 언어입니다.

화면의 정보 계층, 타이포그래피, 레이아웃과 콘텐츠 흐름은 편집 디자인의 원칙을 따릅니다.

### 핵심 특성

* 제목, 숫자와 메타데이터 사이에 명확한 타이포그래피 계층을 둡니다.
* 모든 정보를 동일한 크기와 무게로 표현하지 않습니다.
* 중요한 정보와 보조 정보를 크기, 무게, 위치와 여백으로 구분합니다.
* 카드의 반복보다 섹션, 얇은 구분선과 여백으로 정보를 나눕니다.
* 필요한 경우 비대칭 배치를 사용하여 정보의 우선순위를 드러냅니다.
* 이미지보다 제목, 순위, 변화량과 설명을 우선합니다.
* 편집 기사처럼 읽히는 영역과 데이터 목록처럼 비교되는 영역 사이에 시각적 리듬을 만듭니다.
* 화면의 상단을 장식이나 환영 문구로 과도하게 소비하지 않습니다.
* 실제 서비스 수준의 정보 밀도를 유지합니다.

### 적용 원칙

Signal Editorial은 특정 화면에만 적용하는 스타일이 아니라 Trend Leader 전체의 기본 화면 구성 원칙입니다.

로그인, 관심사 선택처럼 데이터 밀도가 낮은 화면에서도 다음 원칙은 유지합니다.

* 명확한 제목과 설명의 계층
* 불필요한 카드 중첩 방지
* 왼쪽 정렬 중심의 읽기 흐름
* 여백과 구분을 통한 구조화
* 모든 요소를 동일한 모양으로 반복하지 않음

## 6. 보조 시각 언어: Trend Radar

Trend Radar는 데이터의 변화와 상태를 표현할 때만 사용하는 보조 시각 언어입니다.

전체 화면의 배경 테마나 장식 스타일로 사용하지 않습니다.

### 사용 대상

* 순위 상승
* 순위 하락
* 신규 진입
* 변화 없음
* 트렌드 강도
* 데이터 수집 또는 갱신 상태
* 새롭게 포착된 정보

### 표현 원칙

* 변화량을 숫자와 부호로 명확하게 표시합니다.
* 상승, 하락과 신규 상태는 색상뿐 아니라 아이콘, 형태 또는 텍스트로 함께 구분합니다.
* 선, 점과 짧은 신호 표현은 실제 데이터 의미가 있을 때만 사용합니다.
* 동일한 상태 표현을 화면마다 임의로 바꾸지 않습니다.
* 정보보다 시각 효과가 더 강하게 보이지 않도록 합니다.

### 사용 금지

다음과 같은 경우에는 Trend Radar 표현을 사용하지 않습니다.

* 의미 없는 배경 파동
* 장식용 원과 점
* 데이터와 연결되지 않은 펄스
* 지속적으로 반복되는 레이더 애니메이션
* 단순히 화면을 미래적으로 보이게 하기 위한 선과 그래프
* 실제 데이터가 없는 가짜 차트

## 7. 정보 우선순위

Trend Leader 화면에서는 다음 정보가 우선되어야 합니다.

1. 사용자가 현재 보고 있는 정보의 주제
2. 핵심 제목 또는 항목명
3. 순위, 변화량과 현재 상태
4. 정보를 이해하기 위한 요약
5. 카테고리, 출처와 시각 등의 메타데이터
6. 저장, 이동과 같은 보조 행동

이미지는 핵심 정보의 이해를 돕는 경우에만 사용합니다.

이미지가 없더라도 제목, 상태와 요약만으로 정보의 의미를 파악할 수 있어야 합니다.

북마크, 더 보기와 같은 Action은 콘텐츠보다 시각적으로 우선하지 않습니다.

---

## 8. 레이아웃 방향

### 기본 흐름

* 콘텐츠는 왼쪽 정렬을 기본으로 합니다.
* 모든 요소를 중앙 정렬하지 않습니다.
* 정보는 위에서 아래로 자연스럽게 읽히도록 구성합니다.
* 중요도에 따라 영역의 크기와 여백에 차이를 둡니다.
* 동일한 정보 구조를 가진 항목은 비교하기 쉽게 정렬합니다.
* 화면 상단 영역을 불필요하게 크게 사용하지 않습니다.
* 작은 화면에서도 핵심 정보가 먼저 보이도록 합니다.

### 정보 구분

정보 영역은 다음 요소를 우선하여 구분합니다.

1. 타이포그래피 크기와 무게
2. 여백
3. 얇은 구분선
4. 배경 명도 차이
5. 필요한 경우에만 제한적인 surface

그림자와 둥근 카드를 기본적인 정보 구분 방법으로 사용하지 않습니다.

### 화면 밀도

* 정보가 지나치게 성기게 보이지 않도록 합니다.
* 큰 빈 공간을 고급스러움의 기본 표현으로 사용하지 않습니다.
* 사용자가 화면의 핵심 정보와 상태를 짧은 시간 안에 파악할 수 있어야 합니다.
* 데이터 밀도가 높은 화면에서는 비교와 스캔이 쉬운 정렬을 우선합니다.
* 데이터 밀도가 낮은 화면에서도 불필요하게 요소 크기를 키우지 않습니다.

---

## 9. 카드와 Surface 사용 방향

Trend Leader는 카드 사용을 금지하지 않지만, 모든 콘텐츠를 독립된 둥근 카드에 넣는 방식을 사용하지 않습니다.

### Surface 사용이 적절한 경우

* 사용자가 직접 선택할 수 있는 독립 항목
* 주변 콘텐츠와 명확하게 분리되어야 하는 Action 영역
* 배경과 구별되지 않으면 상태 이해가 어려운 영역
* AI 분석처럼 일반 콘텐츠와 다른 의미를 전달하는 영역
* 오류, 경고와 같은 별도의 피드백 영역

### Surface 사용이 부적절한 경우

* 제목과 설명만 있는 일반 섹션
* 모든 목록 항목
* 단순 메타데이터
* 구분선과 여백만으로 충분히 나눌 수 있는 정보
* 화면 안에서 반복되는 모든 콘텐츠

### 모서리와 그림자

* 한 화면에서 지나치게 많은 radius 종류를 사용하지 않습니다.
* 큰 콘텐츠 영역의 모서리를 과도하게 둥글게 만들지 않습니다.
* 그림자는 계층이나 떠 있는 동작을 설명해야 할 때만 사용합니다.
* 구분을 위해 모든 컴포넌트에 그림자를 적용하지 않습니다.

구체적인 radius와 elevation 값은 Design System Snapshot에서 정의합니다.

---

## 10. 이미지 사용 방향

* 이미지는 정보 이해를 돕는 보조 요소입니다.
* 이미지가 제목과 순위보다 먼저 인식되지 않도록 합니다.
* 이미지 중심 SNS 피드처럼 구성하지 않습니다.
* 콘텐츠에 적절한 이미지가 없을 때 의미 없는 대체 이미지를 사용하지 않습니다.
* 이미지 유무에 따라 정보 계층이 무너지지 않아야 합니다.
* 썸네일은 실제 콘텐츠와 연관된 경우에만 사용합니다.
* 장식용 배경 이미지로 텍스트 가독성을 낮추지 않습니다.

구체적인 이미지 비율과 크기는 화면 명세 또는 Design System Snapshot에서 결정합니다.

---

## 11. 타이포그래피 방향

* 화면 제목, 섹션 제목, 항목 제목, 본문, 메타데이터의 계층을 명확하게 구분합니다.
* 제목은 개성이 있지만 한글 가독성을 방해하지 않는 산세리프 계열을 사용합니다.
* 숫자와 순위 정보는 일반 본문과 다른 무게 또는 폭을 사용하여 구분할 수 있습니다.
* 모든 텍스트를 굵게 처리하지 않습니다.
* 핵심 제목과 상태 숫자에만 강한 무게를 제한적으로 사용합니다.
* 본문과 요약은 빠르게 읽을 수 있는 줄 간격을 유지합니다.
* 메타데이터는 본문보다 약하게 표현하되 읽기 어려울 정도로 작게 만들지 않습니다.
* 긴 한글 제목이 포함되어도 레이아웃이 깨지지 않아야 합니다.

폰트 패밀리, 크기, 무게, line height와 letter spacing은 Design System Snapshot에서 정의합니다.

---

## 12. 색상 방향

* 기본 배경은 순백색보다 약간 온도가 있는 밝은 중성색을 지향합니다.
* 주요 본문은 검정에 가까운 고대비 색상을 사용합니다.
* 보조 정보는 본문보다 약하지만 충분히 읽을 수 있는 중성색을 사용합니다.
* 브랜드 강조 색상은 한 가지를 중심으로 사용합니다.
* 브랜드 색상을 모든 요소에 반복해서 사용하지 않습니다.
* 상승, 하락, 경고와 오류 상태 색상은 브랜드 색상과 역할을 분리합니다.
* 상태는 색상만으로 전달하지 않습니다.
* 그라데이션은 실제 데이터 상태나 명확한 의미가 있을 때만 제한적으로 사용합니다.
* 보라색과 파란색 그라데이션을 앱의 기본 배경이나 기본 브랜드 표현으로 자동 사용하지 않습니다.

정확한 브랜드 색상과 상태 색상은 현재 확정되지 않았으며 Design System Candidate에서 제안하고 검증합니다.

## 13. AI 분석 영역의 시각 방향

AI 분석은 일반 설명과 구분되지만, 화면 전체보다 과도하게 강조하지 않습니다.

다음 표현을 사용할 수 있습니다.

* 작은 AI 분석 라벨
* 얇은 인용선 또는 주석선
* 일반 surface와 구분되는 제한적인 배경
* 편집 주석과 유사한 구조
* 출처 또는 분석 시점을 함께 보여주는 메타데이터

AI 영역은 다음과 같이 표현하지 않습니다.

* 전체 화면을 차지하는 챗봇 말풍선
* 보라색·파란색 그라데이션을 통한 관습적인 AI 표현
* 의미 없는 반짝임과 별 모양 장식
* 과도한 로봇 또는 마법 이미지
* 분석 내용보다 AI 브랜드가 먼저 보이는 구성

AI 분석의 구체적인 표시 여부와 정보 범위는 각 Screen Specification에서 정의합니다.

## 14. 키워드와 메타데이터 방향

### 키워드

* 관련 키워드는 의미 없는 pill 버튼의 반복처럼 보이지 않도록 합니다.
* 키워드 간 관계나 중요도 차이가 있다면 타이포그래피, 구분 기호 또는 배치로 표현할 수 있습니다.
* 실제로 선택 가능한 키워드와 단순 정보 키워드를 시각적으로 구분합니다.
* 모든 키워드를 동일한 색과 둥근 배경으로 감싸지 않습니다.

### 메타데이터

* 카테고리, 출처, 수집 시각과 플랫폼 정보는 제목과 요약보다 약하게 표현합니다.
* 작은 텍스트 라벨 또는 단색 아이콘을 사용할 수 있습니다.
* 여러 메타데이터는 일관된 순서와 구분 방식을 유지합니다.
* 출처 플랫폼의 브랜드 색상을 화면 전체에 직접 확장하지 않습니다.
* 메타데이터가 많을 때는 핵심 항목만 우선 노출하고 나머지는 화면 명세에서 정리합니다.

---

## 15. 인터랙션과 상태 방향

* 사용자가 누를 수 있는 요소와 단순 정보 요소를 구분합니다.
* 선택 상태는 배경색만이 아니라 border, 아이콘, 형태 또는 텍스트 변화로 함께 표시합니다.
* 비활성 상태에서도 요소의 목적을 이해할 수 있어야 합니다.
* 처리 중인 Action은 중복 입력을 방지합니다.
* 로딩 상태는 콘텐츠 구조를 완전히 잃지 않도록 합니다.
* 오류와 빈 데이터는 장식보다 문제와 다음 행동을 명확하게 전달합니다.
* 북마크와 같은 보조 Action은 핵심 콘텐츠보다 과도하게 강조하지 않습니다.
* 터치 피드백은 짧고 절제되게 사용합니다.

구체적인 상태 토큰과 컴포넌트 동작은 Design System Snapshot에서 정의합니다.

---

## 16. Motion 방향

애니메이션은 상태 변화의 이해를 돕는 경우에만 사용합니다.

### 허용

* 선택 상태 전환
* 버튼 pressed 상태
* 로딩에서 콘텐츠로의 전환
* 데이터 갱신 상태
* 화면 간 자연스러운 Navigation 전환

### 금지

* 의미 없는 무한 애니메이션
* 지속적으로 반복되는 펄스
* 장식용 레이더 회전
* 정보 확인을 지연시키는 큰 이동
* 모든 카드가 순차적으로 등장하는 과도한 효과
* 화면의 신뢰성을 떨어뜨리는 탄성 효과의 반복

구체적인 duration과 easing은 Design System Snapshot에서 정의합니다.

---

## 17. 접근성과 모바일 방향

* Android 모바일 환경을 우선합니다.
* 세로 화면과 한글 콘텐츠를 기본으로 고려합니다.
* 기준 화면 너비는 360~412dp 범위를 고려합니다.
* Safe Area를 침범하지 않습니다.
* 주요 터치 영역은 충분한 크기를 확보합니다.
* 본문과 배경 사이에 충분한 명도 대비를 확보합니다.
* 상승, 하락, 선택, 오류와 같은 상태를 색상만으로 구분하지 않습니다.
* 아이콘 버튼에는 접근 가능한 이름을 제공합니다.
* 긴 한글 제목과 설명에서도 핵심 정보가 잘리지 않도록 합니다.
* 작은 화면에서도 제목, Action과 상태 정보의 우선순위를 유지합니다.
* 의미 없는 장식은 스크린 리더 탐색 대상에서 제외합니다.

정확한 최소 크기와 대비 기준은 Design System Snapshot에서 구현 가능한 값으로 정의합니다.

---

## 18. 전역 금지 사항

다음 표현은 Trend Leader의 기본 디자인으로 사용하지 않습니다.

* 모든 콘텐츠를 흰색 rounded card에 넣는 구성
* 모든 컴포넌트에 그림자를 사용하는 구성
* glassmorphism
* 보라색·파란색 그라데이션을 기본 테마로 사용하는 구성
* 의미 없는 블롭, 원형, 파동과 레이더 장식
* 실제 데이터가 없는 가짜 차트
* 이모지를 기능 아이콘으로 사용하는 방식
* 일반적인 금융 대시보드를 그대로 복제한 구성
* SNS 피드처럼 프로필 이미지와 게시물 카드가 중심인 구성
* 일반 뉴스 앱 템플릿을 그대로 복제한 구성
* Material Design 기본 컴포넌트를 조정 없이 나열한 인상
* 지나치게 넓은 빈 공간으로 실제 정보량을 줄이는 구성
* 모든 요소를 중앙 정렬하는 구성
* 모든 텍스트를 굵게 처리하는 구성
* “안녕하세요, 사용자님”과 같은 일반적인 환영 문구를 화면의 핵심으로 사용하는 구성
* 정보 전달보다 AI 또는 기술 이미지를 강조하는 구성

## 19. 이 문서에서 결정하지 않는 사항

다음 항목은 이 문서에서 확정하지 않습니다.

* 화면별 이미지 크기와 비율
