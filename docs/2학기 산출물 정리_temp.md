안내 및 예외 사항
 * 주요 활동 지침: 발표(PPT) 시 각 활동에 대한 구체적인 설명과 함께 현재 시점의 진행 상황을 명확히 전달해야 합니다.
 * 예외 사항: 프로젝트의 특성 및 일정 상황에 따라 DB 구축 등 특정 단계는 축소되거나 생략될 수 있습니다.
산출물 분석 및 관리 관점
 * 정량적 지표 중심 구성: 백엔드(API 개수), 프론트엔드(화면 개수), 테스트(테스트 케이스 개수 및 통과율 %) 전반에 걸쳐 진행률을 수치화하여 시각적으로 증명할 수 있도록 설계되어 있습니다.
 * 추적 가능성(Traceability) 확보: 설계 단계(Figma, ERD, API 초안)와 구현 단계 간의 변경점(추가/수정된 API, 미구현 화면)을 비교해 보고서나 PPT에서 개발 지연 요소 및 범위 조정을 논리적으로 방어할 수 있습니다.
 * 문서화 자동화 추천: 산출물 작성 부담을 줄이기 위해 API 문서는 Swagger/OpenAPI 자동 생성 기능을 적극 활용하고, 버그/이슈 리스트는 GitHub Issues 또는 Jira 칸반 보드 캡처 및 CSV 추출로 연계하는 방식이 효율적입니다.
